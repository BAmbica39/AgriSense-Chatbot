# 🌾 Farmer Chatbot

A full-stack AI farming assistant. Users sign up and log in, then ask farming questions in natural
language (crops, soil, irrigation, fertilizers, pests, plant diseases) and get answers generated by
Google Gemini, guided by a farming-focused system instruction.

| Layer    | Tech                                                           |
|----------|----------------------------------------------------------------|
| Frontend | React 19, Vite, React Router, Axios                            |
| Backend  | Python, FastAPI, Uvicorn                                       |
| Database | MySQL (users table)                                            |
| Auth     | PBKDF2-SHA256 password hashing + JWT bearer tokens (PyJWT)     |
| Chatbot  | Google Gemini API via the official `google-genai` Python SDK   |

## How it works

1. **Sign up** (`POST /signup`): the backend validates the input, hashes the password with a random salt (PBKDF2, 600k iterations), and stores the user in MySQL. Plaintext passwords are never stored.
2. **Log in** (`POST /login`): the password is checked against the hash. On success the backend returns a signed JWT that expires after `JWT_EXPIRE_MINUTES`.
3. **Chat** (`POST /ask`): the frontend sends the JWT as `Authorization: Bearer <token>`. Requests without a valid token get `401`, and the frontend then sends the user back to the login page. When the chat page opens, it calls `GET /me` once, so a token that expired since the last visit logs the user out right away.
4. **Answering with Gemini** (`chatbot.py`):
   - The backend checks the message (1–1000 characters) and the user's limits (one question at a time, `CHAT_REQUESTS_PER_MINUTE` per minute). Double-clicks therefore can't trigger extra Gemini calls.
   - It sends the question to Gemini (`GEMINI_MODEL`), together with:
     - a **system instruction** that keeps the model focused on farming, asks for simple structured answers, has it ask follow-up questions when details are missing, and tells it not to invent dosages or facts;
     - the **last few messages** of the conversation (`CHAT_HISTORY_MESSAGES`), so follow-ups like "what about rice?" make sense. Nothing else about the user is sent.
   - Gemini's reply is returned as `{reply}`. The frontend renders its headings and lists.
5. **Failures are never hidden**: a missing or invalid key, quota or rate limits (`429`), timeouts (`504`), network problems, Gemini outages (`503`) and empty replies (`502`) return a clear message. The chat shows it with a **Try again** button. There is no hardcoded fallback answer.

The Gemini API key is only read by the backend from `.env`. It is never sent to the browser, included in API responses, or written to logs, and user messages are not logged either.

### API

| Method | Path      | Auth   | Body                                                        |
|--------|-----------|--------|-------------------------------------------------------------|
| GET    | `/health` | –      | –                                                           |
| POST   | `/signup` | –      | `{username, name, email, password, confirm_password}`       |
| POST   | `/login`  | –      | `{username, password}` → `{access_token, username, name}`   |
| GET    | `/me`     | Bearer | –                                                           |
| POST   | `/ask`    | Bearer | `{message, history?}` → `{reply}`                           |

`history` is optional: up to 10 earlier messages as `{role: "user" | "model", text}`.

Interactive API docs are available at http://localhost:8000/docs while the backend is running.

## Prerequisites

- Python 3.11+
- Node.js 18+ (tested with Node 22)
- MySQL 8 running locally (or any reachable MySQL server)

## Setup

### 1. Backend

```bash
cd farming-chatbot-backend
python -m venv venv
# Windows:
venv\Scripts\activate
# macOS/Linux:
source venv/bin/activate

pip install -r requirements.txt
cp .env.example .env        # Windows: copy .env.example .env
```

Edit `.env` and set the following variables:

| Variable             | Description                                   | Example                     |
|----------------------|-----------------------------------------------|-----------------------------|
| `DB_HOST`            | MySQL host                                    | `localhost`                 |
| `DB_PORT`            | MySQL port                                    | `3306`                      |
| `DB_USER`            | MySQL user                                    | `root`                      |
| `DB_PASSWORD`        | MySQL password                                | *(your password)*           |
| `DB_NAME`            | Database name (created automatically)         | `chatbot_users`             |
| `JWT_SECRET`         | Long random string used to sign tokens        | see command below           |
| `JWT_EXPIRE_MINUTES` | Login session length                          | `60`                        |
| `CORS_ORIGINS`       | Comma-separated frontend URLs                 | `http://localhost:5173`     |
| `GEMINI_API_KEY`     | Google Gemini API key (**backend only**)      | *(your key)*                |
| `GEMINI_MODEL`       | Gemini model used for answers                 | `gemini-3.5-flash-lite` (default)|
| `GEMINI_TIMEOUT_SECONDS` | Max wait for a Gemini reply               | `30`                        |
| `GEMINI_MAX_OUTPUT_TOKENS` | Max answer length (tokens)              | `2048`                      |
| `CHAT_HISTORY_MESSAGES` | Earlier messages sent as context           | `6`                         |
| `CHAT_REQUESTS_PER_MINUTE` | Questions allowed per user per minute   | `10`                        |

Only `GEMINI_API_KEY` is required for the chatbot; the others have the defaults shown.

#### Getting a Gemini API key

1. Go to [Google AI Studio](https://aistudio.google.com/apikey) and sign in with a Google account.
2. Click **Create API key** and copy it.
3. Paste it into `farming-chatbot-backend/.env` as `GEMINI_API_KEY=...` and restart the backend.

Never put the key in the frontend (`VITE_*` variables are visible in the browser) or commit `.env`. To change the model, set `GEMINI_MODEL` in `.env` and restart; no code changes are needed.

Generate a JWT secret with:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

Start the backend:

```bash
uvicorn main:app --reload --port 8000
```

On startup the backend creates the `chatbot_users` database and the `users` table if they don't exist (see `schema.sql`). The server refuses to start if `JWT_SECRET` is missing. If `GEMINI_API_KEY` is missing it still starts (signup and login work) but logs a warning, and `/ask` returns a "not configured" error.

### 2. Frontend

```bash
cd farming-chatbot-frontend/farmingChatBot
npm install
npm run dev
```

Open http://localhost:5173. The frontend calls `http://localhost:8000` by default. To use a different backend URL, copy `.env.example` to `.env.local` and change `VITE_API_URL`.

## Testing

Backend tests use FastAPI's `TestClient` with in-memory fakes in place of MySQL and Gemini, so they run without a database, an API key or internet access, and cost nothing:

```bash
cd farming-chatbot-backend
python -m pytest -v
```

They cover:

- signup, login, duplicate users, validation errors (including blank usernames) and password hashing;
- protected `/ask` access (no token or an invalid token);
- the Gemini request: model taken from config, system instruction, and history trimmed to the configured size;
- Gemini failure handling: missing key, invalid key, unknown model, 429 quota/rate limit, server errors, network failure, timeout and empty reply;
- per-user limits: one request at a time and N per minute;
- the database-down (503) path.

Frontend checks:

```bash
npm run lint
npm run build
```

### Manual end-to-end check

1. Start MySQL, the backend, and the frontend.
2. Open http://localhost:5173 and create an account. You are signed in automatically and land on `/chat`.
3. Click an example question (for example "How to grow tomatoes?") or type your own and press Enter. A Gemini-generated answer appears, often with headings or numbered steps.
4. Ask a follow-up such as "My tomato leaves have brown spots". The bot should ask about missing details (location, symptoms) or answer using the earlier context.
5. Ask something unrelated ("Who won the cricket match?"). The bot should politely steer back to farming.
6. Stop the backend and send a question: a "Cannot reach the server" message with a **Try again** button appears. Restart the backend and click **Try again**.
7. Click **Log out**, then open http://localhost:5173/chat directly. You are redirected to login.

## Gemini limitations and troubleshooting

- **Answers can be wrong.** Gemini can make mistakes, and the system instruction asks it to admit uncertainty and avoid chemical dosages. The UI shows a reminder to confirm important decisions with a local expert.
- **Free-tier quotas.** Free API keys have per-minute and per-day request limits. When they are reached, the chat shows "too many requests or its usage quota is used up". Wait and retry, or check usage in Google AI Studio.
- **Answers take a few seconds**, longer than the old CSV lookup. The UI shows "Writing an answer…" while waiting. Requests time out after `GEMINI_TIMEOUT_SECONDS`.
- **Limits are per backend process.** `limits.py` keeps its counters in memory. That is fine for one server, but several servers would need a shared store such as Redis.

| Message in the chat | Likely cause | Fix |
|---|---|---|
| "The AI assistant isn't configured on the server yet." | `GEMINI_API_KEY` missing | Add it to the backend `.env`, restart |
| "The AI assistant isn't set up correctly on the server." | Invalid or restricted key, or a `GEMINI_MODEL` that is unknown or retired (Google retires older models; the backend log shows Gemini's message, which usually names the replacement) | Check the backend terminal log, fix `.env`, restart |
| "…too many requests or its usage quota is used up." | Gemini rate limit or quota | Wait a minute, or check quota in AI Studio |
| "You're asking questions very quickly…" | App's own per-user limit | Wait a minute or raise `CHAT_REQUESTS_PER_MINUTE` |
| "Couldn't reach the AI service…" / "took too long" | No internet on the server, firewall, slow network | Check the connection, retry |
| "Cannot reach the server…" | Backend not running | Start the backend |

## Security notes

- Secrets live in `.env` (git-ignored). `.env.example` contains placeholders only.
- The Gemini key and system instruction stay on the backend. The browser only talks to this FastAPI server, never to Gemini directly.
- Passwords are salted and hashed. Login errors don't reveal whether the username exists.
- All SQL queries are parameterized.
- The JWT is stored in `localStorage` for simplicity. A production app might use httpOnly cookies instead.
